# PH-VOICE-2026-10-05-R1 — исправление голоса до проверенного обновления

Это постановка для **нового исполнительного окна ChatGPT**. Аудит и независимая приёмка остаются в контрольном окне. Нужно внедрение, а не ещё один общий аудит или новая архитектура.

## 0. Какая задача сейчас действующая

Действующий идентификатор: **PH-VOICE-2026-10-05-R1**. Исправить в Projects Hub остановку микрофона через 20–30 секунд, отсутствие живого текста собственной речи справа и потерю доступности недавно наговорённой мысли при восстановлении Live.

Прочитать подтверждённый аудит:

https://github.com/onedayonemasterpiece/projects-hub/blob/8792ec051cfa600ced090ce829dd6ed72208ca97/docs/audits/voice-long-input-20261005.md

Не продолжать вместо этой задачи старые постановки про owner Codex orchestration, общий Android updater, embeddings, Street Story или другие проекты. На «продолжи» восстанавливать checkpoint именно PH-VOICE-2026-10-05-R1 и проверять, что результат/ветка относятся к нему. Не выполнять заново уже принятые изменения и неизвестно завершившиеся side effects.

Использовать GitHub и Codex DevCoveer Direct Ops. Исходники, постановку и смысловые решения пишет сама ChatGPT. OpenCode допустим для применения подготовленных изменений, тестов и детерминированной сборки/раскатки; не отдавать ему самостоятельное проектирование вместо ChatGPT. Не запускать native Codex без отдельного разрешения пользователя.

## 1. Продуктовый результат

Пользователь включает микрофон и говорит несколько минут, видит распознаваемую **этой же Live-моделью** собственную речь в правом сообщении и затем продолжает содержательный диалог. Приложение не выключает микрофон из-за дефектного резервирования бюджета. Технический сбой не выглядит как штатное «Готова слушать». Ещё не оформленная в документ/память/задачу мысль остаётся доступной после восстановления.

Непрерывный пяти­минутный ввод — обязательный целевой сценарий приёмки, а не уже доказанная возможность. Десять минут — дополнительная проверка запаса; сообщать измеренный диапазон, а не теоретический предел модели. Пользователь не обязан каждые 20–30 секунд останавливаться, чтобы система «успела запомнить».

Сохранить текущую архитектуру: одна центральная Мира; клиент → authenticated same-origin WSS → backend → Live provider. API keys и GitHub взаимодействие остаются на backend. Не вводить второй скрытый ASR/LLM, браузерный SpeechRecognition вместо model-derived transcript, альтернативный socket/VAD/semantic router, смену ключей после ready или bypass общей authority. Не переделывать дизайн; сохранить плавающие острова и существующий messenger UI.

Читать актуальные AGENTS, защищённый requirements contract и применимые incident/reuse инструкции. Для runtime использовать точный релизный каталог: root `source` у host_probe может быть старым checkout.

## 3. Первая поставка: устранить доказанный budget cutoff

Не тратить новую итерацию на поиск причины с нуля. Для сессии 05.10.2026 08:48:26–08:48:57 UTC реестр authority подтвердил **terminal_reason=RESOURCE_TOKEN_BUDGET**. Grants: 16384 + 22518 + 16384 = 55286 при minute_token_limit=60000. Примерно через 29 секунд старый SDK запросил ещё минимум 16384 для малого аудиочанка и получил отказ. Это внутренние reservation units, не billing.

`deploy/devcoveer_install.py` закрепляет старый SHA SDK. В shared 0.1.11 уже имеются уменьшенный default quantum 1024, shortfall reservation и right-sizing после окончательного budget denial. Сначала оценить и переиспользовать эти исправления, обновить единый installation/release contract и убедиться, что новый SDK действительно установлен в release venv.

Протестировать: маленький audio chunk при остатке authority меньше bulk quantum; несколько последовательных 29-секундных окон; setup + audio + text/tool result; definitive denial и transport-unknown outcome; истечение grant и lease; параллельные пользователи. Не продлевать неявно spend deadline старого carry, не расходовать неподтверждённые units, не дублировать выдачу grant после неизвестного результата.

Не считать исправлением увеличение 60000, отключение limiter, local-key fallback после успешной admission, смену provider key или бесконечный restart. При реально исчерпанном бюджете поведение должно быть честным, ограниченным и сохраняющим доступный source, без обхода policy.

## 4. Вторая поставка: ошибки, причины остановки и наблюдаемость

В shared browser client событие `error` вызывает `stop(reason=provider_error)`. Projects Hub не обрабатывает error в `applyLiveEvent`, игнорирует detail/reason во втором аргументе onState; onTiming не подключён. Исправить общий контракт и продуктовую обработку вместе.

Нужен явно типизированный терминальный outcome: user stop / capture error / connection failure / provider failure / resource denial / app lifecycle. Не называть любое выключение «Готова слушать». Показывать понятную причину, состояние записи и доступное восстановление. Первичная ошибка не должна затираться последующей ошибкой cleanup.

Подключить ограниченную безопасную телеметрию, используя существующие события, а не вторую платформу мониторинга:

- Correlation: task/test run, attempt, session, source, connection generation, backend release, JS build, native version, shared versions/provenance.
- Capture/transport: sample count, last frame age, bounded queue, отправлено/принято/durable watermark, playback suppression intervals.
- Provider/transcript: типы полученных полей, число и длина interim/final fragments, sequence/revision, время первого/последнего фрагмента; сопоставление с WSS и DOM.
- Resources: need/requested/granted/remaining, grant/lease deadlines, definitive result, retry-after и terminal reason.
- Stop: source of stop, explicit user action versus automatic cleanup, исходный code и итог.

Не логировать тексты личной речи, аудио, tokens/cookies, приглашения, API keys, tool payloads с приватными данными. Проекция public UI events, приватное source-хранилище и operational log — разные поверхности. После ошибки доказательства должны сохраняться, а не исчезать вместе с in-memory ring.

## 5. Третья поставка: настоящая транскрипция до конца длинной реплики

В backend/source сохранено 27.576 секунды звука, но только 13 символов финального пользовательского текста. Обработчик interim в коде уже есть; повторное его добавление не является решением.

Для текущих model/setup включить безопасные счётчики и пройти реальный маршрут:

`provider interim/input transcription → framework event → product observation → WSS frame → client event → React state → реально отображённый правый bubble`.

Определить первый этап, на котором исчезает или опаздывает текст. Официальный контракт: https://ai.google.dev/api/live — `interimInputTranscription` обновляется во время речи, input transcription не имеет гарантированного порядка относительно прочих сообщений. Поведение конкретной модели/конфигурации подтвердить фактическим запуском.

Различать provisional и finalized text. Обновление промежуточной гипотезы может заменять прежнюю, а не всегда дописывать её; тестировать корректировки, поздние финальные фрагменты, reordered events, interrupted, replay и reconnect. Не принимать текущий merge строк за доказанный универсальный протокол.

Устранить потерю текста из-за App `.slice(0,4000)`, host preview 2000 и сброса индексов. Допустим bounded viewport/virtualization/пагинация, но текущая мысль целиком доступна, виден растущий хвост, финальный текст можно дочитать из source. Interim preview 1200 не должен быть единственной доступной версией речи.

Первый model-derived текст должен появляться во время непрерывной речи, не только после паузы или stop. Цель приёмки: первый фрагмент не позднее 5 секунд от начала разборчивой тестовой речи; p95 доставки уже полученного backend transcript event до DOM не более 750 ms. Это заданные продуктовые цели, не обещанный SLA Google. Измерять реальные времена; при отклонении не подменять провайдера mock-событиями.

До получения текста показывать честное «Микрофон работает; текст ещё не получен» с живыми подтверждениями transport/durable state. Только model-derived текст маркировать как распознанный. Не создавать иллюзию слышимости локальным ASR или анимацией.

## 6. Паузы, возврат микрофона и сохранение незавершённой мысли

VAD завершает реплику, не всю сессию. Сохранить нормальный живой диалог. Проверить паузы 1/3/6/10 секунд, ответ Миры и следующую пользовательскую фразу без повторного включения микрофона. Для длинной мысли с паузами выбрать минимальный вариант, позволяющий пользователю удерживать/явно завершать свою реплику, если provider VAD не даёт нужного результата. Не вводить ради этого второй transport или отдельного агента; не менять архитектуру только ради 30-секундного симптома, уже объяснённого бюджетом.

`continuousCapture=true` не отменяет `suppressCaptureDuringPlayback=true`: речь во время playback сейчас может отбрасываться до sender. Проверить и исправить согласованную capture/barge-in политику в shared framework. Не просто снять защиту и получить эхо. Нельзя показывать «Слушаю», если пользовательская речь фактически отбрасывается без сохранения; такое состояние должно быть явно обозначено и проверено.

Прекратить полагаться на 8×700 символов истории как на сохранность мысли. Проверить все слои: product store, shared session host и DialogueHistory. Сохранять exact source/revisions и unresolved/pending state; предоставить той же Мире узкий actor-private инструмент чтения собственного transcript/source страницами. На новую provider session передавать ссылки на доступные незавершённые мысли и текущую инструкцию, а не только усечённые начало/конец.

Если transcript не финализирован, сохранять аудио и восстанавливать его через существующий явный buffered-source путь той же Live-модели. Не проигрывать вслепую stale unacknowledged audio в новый realtime stream. Source recovery не разрешает заново исполнять уже принятые команды. Нужны command ID/idempotency/revision/readback; pending мысль не может самопроизвольно заместить новую просьбу пользователя. Сохранить изоляцию actor/workspace/conversation и действующую retention/privacy policy.

Это не повод прекращать доступную разработку и не разрешение назвать релиз полностью принятым.
