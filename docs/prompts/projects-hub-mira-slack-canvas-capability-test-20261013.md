# Проверить, может ли Mira создавать и редактировать Slack canvas

Ты работаешь в существующем проекте Projects Hub и имеешь его текущий технический контекст. Выполни небольшой реальный capability test через уже разрешённый маршрут Slack-бота Mira. Не строй полноценную интеграцию и не занимайся рефакторингом продукта.

## Цель и адресат

Проверить цепочку: **Mira создаёт canvas в указанном канале → записывает простой текст → читает его из Slack → изменяет свой тестовый текст → повторно читает и проверяет результат**.

Исходные идентификаторы:

- workspace: `T0C82495TK5`;
- единственный разрешённый канал: `C0C872SJFA7`;
- приложение Mira: `A0C8QLFF1U5`;
- bot ID: `B0C8QLEMMFX`;
- переданный идентификатор автора: `U0C8PNGBTSP`.

Проверь фактическую связь этих идентификаторов; не считай автоматически, что переданный author ID совпадает с bot user ID. Для создания и правки нужен именно действующий бот Mira, а не пользовательский токен или другое приложение.

Гипотеза: редактирование через API может зависеть от платного тарифа. Это **не установленный факт**. Нужно получить доказательный результат для этого workspace, текущего токена и конкретного canvas. Успешное сообщение в канале не доказывает работу canvas API.

## Границы разрешения

Пользователь разрешил создать один тестовый canvas и записать/изменить в нём безвредный тестовый текст в указанном канале. Не требуется повторное согласование именно этого теста. Однако:

- Не меняй тариф, биллинг, OAuth scopes, установку приложения, токены, членство в канале, владельца и права доступа. Если это необходимо, останови зависимую часть и укажи минимальное действие пользователя.
- Не создавай standalone canvas вне этого канала, другие каналы или сообщения-объявления. Не публикуй реальные проектные данные, упоминания пользователей, секреты или внешние ссылки в тестовом тексте.
- Не удаляй canvas или разделы, даже после теста. Не перезаписывай существующее содержимое целиком. Не используй `replace` без `section_id`.
- Существующий рабочий canvas сохрани. Изменять его можно только при явном отдельном разрешении на тестовый блок именно в нём либо если надёжно установлено, что это созданный в рамках этого же теста объект, который нужно продолжить после прерывания. Сам факт доступности на запись не является разрешением. Иначе `BLOCKED`, без записи.
- Используй существующий авторизованный bot route проекта. Не извлекай чужие токены и не подменяй бота пользовательской сессией. Не выводи токены, cookies, Authorization headers или содержимое секретных конфигураций в логи, отчёт и коммиты. Если разрешённого маршрута нет, сообщи блокер.

## Что известно из актуальной официальной документации

Ссылки проверены 13 октября 2026 года; перед исполнением сверяй изменившуюся сигнатуру с документацией.

1. [`conversations.canvases.create`](https://docs.slack.dev/reference/methods/conversations.canvases.create/) создаёт channel canvas, принимает bot token с `canvases:write`, возвращает `canvas_id`. При существующем canvas возможен `channel_canvas_already_exists`; его ID ищется в `channel.properties.canvas` ответа `conversations.info`. Доступ привязан к каналу.
2. [`canvases.create`](https://docs.slack.dev/reference/methods/canvases.create/) также описывает параметр `channel_id`, обязательный для free teams, и ошибки `free_team_canvas_tab_already_exists` / `free_teams_cannot_create_non_tabbed_canvases`. Поэтому не выводи «все canvas API платные» из общего текста или старых статей. Для этого теста основной маршрут — channel canvas; не создавай запасной standalone объект.
3. [`canvases.edit`](https://docs.slack.dev/reference/methods/canvases.edit/) принимает bot token с `canvases:write`; за вызов поддерживается одна операция. Для адресной замены нужен проверенный `section_id`.
4. [`canvases.getContent`](https://docs.slack.dev/reference/methods/canvases.getContent/) — существующий официальный метод: `POST`, аргументы `canvas_id`, необязательный `content_type: "markdown"`; bot/user scope `canvases:read`; полный текст возвращается в `content`. Не выдумывай `canvases.get`/`canvases.info` и не считай отсутствие SDK-обёртки отсутствием API.
5. [`canvases.sections.lookup`](https://docs.slack.dev/reference/methods/canvases.sections.lookup/) с `canvases:read` ищет section IDs по `criteria.contains_text` и, при необходимости, `section_types`. Это поиск секций, а не замена чтения полного текста.
6. [`files.info`](https://docs.slack.dev/reference/methods/files.info/) с `files:read` может дать доступные метаданные файла, автора и permalink. Используй реальные поля ответа, не обещай наличие каждого поля у canvas. [`auth.test`](https://docs.slack.dev/reference/methods/auth.test/) и [`bots.info`](https://docs.slack.dev/reference/methods/bots.info/) помогут проверить действующего субъекта.
7. [`canvases.access.set`](https://docs.slack.dev/reference/methods/canvases.access.set/) содержит отдельную формулировку о paid plan. Не переносить её автоматически на другие методы. Этот метод в тесте **не вызывать**.

## План исполнения

### 1. Read-only preflight

Найди в проекте существующий Slack client/adapter и безопасный способ сделать минимальные вызовы от Mira без изменения production-конфигурации. Не запускай общий workflow, который может иметь посторонние побочные эффекты.

Через `auth.test` проверь workspace и фактического bot user; через доступную метаинформацию/bots.info свяжи bot ID и app ID. Сохрани только несекретные доказательства. При несовпадении workspace/бота остановись до записи.

Прочитай сведения о канале и его canvas через `conversations.info` с текущими правами. Сохрани имя, ID, наличие canvas, его ID и доступность боту. Не трактуй ошибку чтения как отсутствие canvas. Если не удаётся безопасно установить исходное состояние, остановись.

Проверь уже выданные права через доступные метаданные/ответы, не только manifest: для записи требуется `canvases:write`, для основного readback `canvases:read`, для метаданных через files.info — `files:read`; чтение канала зависит от его типа. Не запрашивай scopes «на всякий случай». Подтверждённый тариф запиши, если он доступен без изменения настроек; иначе `plan: unknown`.

### 2. Создание с первичным содержимым

Если canvas отсутствует, создай один через `conversations.canvases.create` с точным `channel_id` и начальным содержимым. Сгенерируй один `run_id` вида `MIRA-CANVAS-TEST-<UTC timestamp>-<short random suffix>`, сохрани локально и повторно используй после прерываний.

Пример тела запроса, подставить единственный run_id:

```json
{
  "channel_id": "C0C872SJFA7",
  "title": "Mira — проверка canvas",
  "document_content": {
    "type": "markdown",
    "markdown": "## MIRA-CANVAS-TEST-<run_id> revision-1\n\nБезвредная проверка записи ботом Mira."
  }
}
```

Один раз проверь `ok`, сохрани реальный `canvas_id`, request ID при наличии, UTC-время и очищенный ответ. Затем повторно прочитай сведения о канале и установи связь полученного canvas с целевым каналом.

Если есть canvas от этого же запуска, продолжи по сохранённому ID после readback. Если API сообщил `channel_canvas_already_exists` или лимит вкладки, сначала прочитай существующее состояние; не создавай второй объект другим методом.

### 3. Первичный readback и авторство

Вызови `canvases.getContent` с полученным ID. Проверь наличие уникального маркера, `revision-1` и точного тестового текста. Сохрани небольшой безопасный фрагмент ответа и его хеш. Входной JSON запроса, `ok: true` записи и section lookup сами по себе не считаются подтверждением фактического текста.

Проверь автора через доступные метаданные, связав его с bot user Mira. Различай creator/owner и acting editor: успешный запрос от проверенного бота доказывает субъект операции, но поле owner не всегда доказывает автора конкретной правки. Если metadata недоступны, прямо укажи, что проверено через identity вызова, а что независимо не подтверждено. Не изображай поле автора, которого API не вернул.

Если чтение или авторство не удалось подтвердить, не продолжай слепую правку. Отметь успешные этапы отдельно и общий `BLOCKED`.

### 4. Адресная правка и повторное чтение

Через `canvases.sections.lookup` найди заголовок с точным уникальным маркером и `revision-1`, например с `section_types: ["h2"]`. Продолжай только при единственном однозначном совпадении и уверенности, что затрагивается исключительно твой тестовый заголовок.

Один вызов `canvases.edit`: `operation: "replace"`, проверенный `section_id`, новый markdown заголовка с тем же маркером и `revision-2`. Не передавай всю исходную страницу и не меняй другие разделы. Если section boundary неясна, остановись вместо рискованной замены.

После ответа повтори `canvases.getContent` независимо от локального состояния. Проверь `revision-2`, отсутствие старого `revision-1` в тестовом заголовке, сохранность тестового абзаца и любого нетестового содержимого. Учитывай нормализацию markdown, но не прячь реальные различия. Повторно зафиксируй бот-субъект и доступные сведения о редактировании.

### 5. Неопределённые ответы и ошибки

При timeout, разрыве соединения, `internal_error` или `fatal_error` запись могла состояться. Сначала readback/проверка состояния, затем решение о повторе; никогда не повторяй создание или вставку вслепую. Если результат невозможно установить, `BLOCKED: uncertain_write`, с перечнем возможных изменений. При rate limit соблюдай `Retry-After`. Не обходи отказы доступа другими credentials или маршрутами.

Разделяй причины: `missing_scope` (с указанием безопасных `needed/provided`, если они вернулись), токен/идентичность, доступ к каналу/canvas, политика workspace, лимит free-плана, некорректный payload, отсутствие метода в используемой обёртке и временная ошибка. `canvas_not_found` может означать отсутствие видимости. `canvas_disabled_user_team` само по себе не доказывает платность. Вывод о тарифе требует явного ответа Slack или подтверждённых сведений плана; не подменяй ими другие блокеры.

## Результат

Верни короткий отчёт и безопасные доказательства:

- `PASS` только при подтверждённых Mira/workspace, создании этим ботом, связи с каналом, первичном содержимом, адресной правке и независимом повторном readback. Иначе `BLOCKED` с точным незавершённым этапом; не скрывай частичный успех.
- Фактические app ID, bot ID, bot user ID, workspace/channel/canvas ID; проверенный permalink из ответа Slack или реально проверенного UI, без выдуманной ссылки. Если permalink недоступен, так и напиши.
- По каждому этапу: метод, UTC-время, HTTP status и Slack `ok/error` при наличии, краткое доказательство. Приведи тестовый текст до и после.
- Ответ на гипотезу: «в этом workspace edit прошёл» либо конкретный подтверждённый блокер; при неизвестном тарифе не делай вывода о free/paid.
- Что осталось в канале после теста, включая частично созданный canvas; ничего не удаляй автоматически.
- Если `BLOCKED`: одно минимальное действие для разблокировки и точный адресат/объект. Если требуется расширение разрешений, опиши его и дождись отдельного согласования. Не предлагай апгрейд, если он не подтверждён причиной ошибки.

Сохрани отчёт в обычный локальный файл проекта без секретов. Не создавай PR, не делай commit/push и не разворачивай интеграцию: задача заканчивается доказанным capability result или конкретным блокером.


## Продуктовые варианты после теста (не реализовывать в этом задании)

- **Canvas «Заметки»**: удобен для перечитывания, заголовков и совместной правки; сначала доказать API в текущем workspace. Если редактируются и Canvas, и Projects Hub, отдельно определить владельца версии и конфликт правок.
- **Один тред «Заметки», ответ = заметка**: простой хронологический журнал коротких мыслей. У ответов нет собственных вложенных тредов, поэтому обсуждения разных заметок перемешиваются. Mira может менять свои сообщения; обычный пользователь не редактирует сообщение бота как своё.
- **Canvas-оглавление**: заголовок, краткая аннотация и ссылка на исходную заметку Projects Hub. Меньше дублирования и конфликтов, подходит длинным заметкам.
- **Закреплённая ссылка на заметки проекта**: минимальный вариант без зеркалирования, но чтение откроет Projects Hub.
- **Отдельное сообщение на заметку**: позволяет обсуждать каждую отдельно, но возвращает уже отвергнутую владельцем схему множества тредов; не внедрять без нового решения.

Рекомендация: сначала проверить Canvas, затем выбрать между полным блокнотом и оглавлением. Projects Hub сохраняет стабильные ID и проектные результаты; Slack не должен становиться единственным архивом. На Free просмотр истории сообщений ограничен 90 днями, старые данные удаляются по политике хранения; закрепление сообщения не заменяет хранение. Не расширять этот тест до синхронизации или новых подписок.
