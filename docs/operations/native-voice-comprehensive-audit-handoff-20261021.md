# Projects Hub — сквозной аудит native voice: версия, прошлые прогоны, журналы и открытые P0

**Срез 21 октября 2026.** Это публичный указатель на технические факты и **приватные** пакеты испытаний в Slack. НЕ отчёт о принятом продукте и НЕ замена самостоятельному чтению реального исходного кода.

## 1. Цель, репозитории, фактическое состояние

**Цель владельца:** один Android-пакет com.kenigevents.projectshub с Мирой, естественные голосовые диалоги до **90 минут** на Samsung S21 Ultra, без самопроизвольного Stop, потери речи или старых ответов, с перебиваниями, короткими паузами, сменами сети, восстановлением Google GoAway, корректной транскрипцией и аудиохвостами. Не терять оригинальные Opus/WVS, не подтверждать данные до fsync/commit; четыре параллельных помощника плюс региональная RKB-нагрузка. Зелёный CI не равен физической приёмке.

**Читать самостоятельно актуальные main и PR:**
- [Projects Hub](https://github.com/onedayonemasterpiece/projects-hub): android, src/projects_hub, web, scripts, tests. [Операционная история и требования](single-app-voice-20261020.md), [канонический handoff](../prompts/projects-hub-native-voice-canonical-handoff-20261020.md).
- [Общий SDK live-interaction](https://github.com/onedayonemasterpiece/live-interaction): android/platform, android/src, python/live_interaction, tests. Нет разрешения строить второй голосовой транспорт вместо общего SDK.

**Что является production при составлении:** подписанный [Android v80](https://github.com/onedayonemasterpiece/projects-hub/releases/tag/android-v80), версия 0.1.62+80, исходный SHA 59c71a635f5aff9a98150d861053977f72191fb0; работающий backend того же SHA, SDK rc17 SHA 404b013a66546a1020f3a547fd978c89571be53e. Доказанной физической 90-минутной приёмки v80 нет.

**Следующая ещё НЕ выкаченная продуктовая версия:** SDK [PR70](https://github.com/onedayonemasterpiece/live-interaction/pull/70) уже merged и [rc18](https://github.com/onedayonemasterpiece/live-interaction/releases/tag/v0.4.0-rc.18) опубликован, SHA e710e8e8143a3724d16250a6e439ccd178c279ca. ## 4. Технические проблемы и прежние аудиты

**Реализовано до v80:** session-scoped recovery, отказ от autoplay вчерашних ответов, раздельные response A/B с delayed terminal/generation_complete, игнорирование старого unbound ACK без разрешения ложного ACK, ingress slots для 10-мс пакетов, Android LRU открытых журналов, пакетная запись выходных Opus-страниц в одной SQLite транзакции. Это не доказывает end-to-end long soak.

**Кандидат PR207/rc18:** продуктовый NativeVoiceStore.appendBatch с одной синхронизацией файла на <=6 оригинальных пакетов, SDK DurableSourceStore.appendBatch с безопасным fallback, буфер <=100мс, flush на turn/EOS/idle, ACK только после sync, отказ при неверной последовательности, защита server cursor overrun, SQLite rollback guard и диагностический код для I/O contention. Нужна критическая проверка torn-tail, partial duplicate + new suffix, journal quota, epoch changes, остановки во время неполной пачки, concurrent output/played/ACK и crash recovery. **Это ещё не подтверждённый продакшен на Samsung**.

**Не закрытые P0/P1:**
1. **Контеншн Android.** NativeVoiceStore всё ещё использует общий synchronized монитор на mic append, output append, played и commit receipt; fsync делается внутри. Сравнить latency, high-water run.pcm, AudioTrack underruns, влияние 700–1200мс fsync и надёжность group commit. Не выносить fsync за монитор без доказанного thread/close/eviction fencing.
2. **Контеншн backend.** Единый EncodedVoiceIO и общий SQLite RLock у всех голосовых сессий; uplink по-прежнему может делать COMMIT на каждый пакет даже после исправления downlink. Нужны числовые метрики IO wait, lock wait, commit by direction, event loop p99/max, ingress-lane head-of-line и fairness для четырёх пользователей. В Projects Hub SQLite WAL + synchronous=FULL — не отключать ради скорости.
3. **STALE и восстановление.** Исследовать, почему уже server-durable stale-frame может остаться не спроецированным провайдеру; восстанавливает ли повторный сокет portions/VAD boundaries; точную причину отдельного socket gap второго v79 теста. Не считать ACK durable равным provider speech admission.
4. **Микропаузы и barge-in.** Проверить NativeEncoder.observeVoice, PORTION_END, 480мс quiet gating, ответ до окончания мысли, cancel/playhead и distinguish intended/false interruption. Точное число ошибочно отрезанных слов **не доказано**.
5. **Текст.** Native partial captions заблокированы CAPTION_CLOCK_UNVERIFIED до доказанной шкалы source/sample clock; canonical final Google сокращал первую RU фразу. UI display может не проскроллить новые сообщения: владелец в старой проверке нашёл тексты после ручной прокрутки. Не объявлять это полной потерей сервера.
6. **Длинная эксплуатация.** Google session resumption / GoAway / context compression, sample clock drift, Wi-Fi↔LTE/BT, Doze/thermal, source limits (старый лимит 250k чанков на 83 минуте поднят до 400k, что не равно performance), journal/SQLite retention, четыре голоса и совместное использование DevCoveer другими сервисами.
7. **Observability и безопасность.** UTC+monotonic, actor/session/source/turn/attempt/generation, trigger user Stop vs fatal Stop, source original → server durable → provider admitted, output archived → device durable → actual played. Не выводить сырые личные PCM/тексты, токены или device secrets в публичные логи.

**Предыдущие заключения Opus 5.5:** dvt_fe2d2d35edf0440fb4699627b75ea879 (три независимых P0, 18 failure-injection сценариев); dvt_4e81b45c267b4d60a026e9f8b1acb48c (Android .wvs fsync/rollback/quotas); dvt_1dad040d036149948f04063c3ece7003 (SDK capture→encode→durable→ACK, semantic STALE). Вызовы использовали **provided_only** и частичные актуальные выдержки, НЕ самостоятельное сканирование полного репозитория — прямому Opus нужно восполнить это самостоятельно.

## 5. Что требуется от нового независимого аудита

Самостоятельно прочитать текущий код обоих репозиториев и точные diff PR69/70/205/207; сверить предыдущие и новые Android/backend/audio evidence по версиям. Разделить **код доказан**, **логи доказали**, **гипотеза**, **не хватает измерения**. Выдать краткий приоритет P0/P1, точный patch-level diff по функциям и ожидаемую нагрузку/latency, не менее 10 детерминированных failure injections (fsync 700–1200мс, late EOS, overrun ACK, 90мин, GoAway, long mic pause, 4 sessions) и план физической 15–20 / 90-минутной проверки. Не предлагать отключение fsync, потерю исходных чанков, бесконечный queue, снятие waveform/VAD age limits, второй клиент, авто-новые provider sessions или удаление личных .wvs. **Результат — минимальные конкретные изменения, которые можно реализовать и проверить, а не новая архитектура и не очередной отчёт.**
