## 1. Вывод

- **«Нулевого контекста» нет.** У разговора всегда есть текущий проект, и он — цель по умолчанию. Мире не нужно угадывать проект с нуля: она меняет цель, только если человек назвал другой проект или сказал «это для себя».
- **Личное — это просто личный проект.** Обычный проект без других людей. Отдельный признак видимости на каждой записи, который предлагали ревью 25 и прошлая версия этого документа, не нужен.
- **Ошибку исправляют, а не предотвращают вопросами.** «Это не сюда, это в подкаст» или «это для себя» переносит запись одной фразой.
- **Остаются три недостающие вещи:**
  1. личный проект и всегда заданный текущий проект;
  2. справочник предметов с именами: спикеры, выпуски, участие;
  3. правка предметов с ревизией и квитанцией.
- **Поиск по архиву для этой вертикали не нужен.** PH-US-14 остаётся открытым to-be. Всё работает без dot, dot получает те же данные по MCP.

## 3. Куда идёт сказанное

```
человек говорит                         текущий проект виден вверху
   │
   ▼
1. голос сохранён (source, ревизия расшифровки)       ← ничего не теряется
   │
   ▼
2. цель по умолчанию — текущий проект
   ├─ назван другой проект     → он
   ├─ «для себя», «лично»      → личный проект
   └─ «переключись на подкаст» → смена текущего проекта, разговор продолжается
   │
   ▼
3. внутри проекта Мира ищет предмет: subject_find
   ├─ явная ссылка или открытая карточка → она
   ├─ один кандидат по имени или дате    → он
   ├─ два и больше                        → один короткий вопрос с отличием
   └─ ни одного                           → новая идея или новый предмет
   │
   ▼
4. запись: memory_commit или subject_update с ревизией и command_id
   │
   ▼
5. квитанция одной фразой: что и куда
   │
   ▼
6. исправление одной фразой:
   «на субботу»              → тот же предмет, новая ревизия
   «это не сюда, это в X»    → запись переносится в X
   «это для себя»            → запись переносится в личный проект
```

Отдельный сервис, модель или слой маршрутизации не нужен. Мира понимает смысл, backend отдаёт кандидатов в доступных проектах и проверяет права.

**Правила:**
- **Явная ссылка сильнее похожести.** Кандидаты ищутся сначала в текущем проекте, потом в остальных доступных.
- **Уточнение только при неоднозначности, влияющей на запись.** Вопрос один и короткий.
- **Несколько проектов в реплике** дают раздельные записи. У каждой своя цель и ссылка на тот же source.
- **«Спикер может в пятницу» меняет только доступность в участии.** Встречу, приглашение или обязательство такая фраза не создаёт.
- **Новый спикер** — это новая персона-предмет, а не новый участник projects-hub.

## 4. Что дополнить

### Данные

| Что | Минимум | Истории |
| --- | --- | --- |
| Личный проект | Обычный проект, где пользователь — единственный участник. Создаётся при первом входе, включая вход по приглашению, в том же workspace. Сейчас заметки проекта требуют привязанного репозитория GitHub; личный проект должен работать и без него | PH-US-78, PH-US-04, PH-US-07 |
| Текущий проект всегда задан | Фокус разговора не бывает пустым, по умолчанию это личный проект. В интерфейсе вверху есть ручное переключение | PH-US-79, PH-US-06 |
| Права на память | Новая память всегда с проектом. Чтение и запись проверяют права на проект. Старые записи без проекта переносятся в личный проект автора исходного голоса | PH-US-04 |
| Предмет | `subjects`: id, проект, вид (персона, выпуск, мероприятие, идея), название, алиасы, поля, ревизия, кто и когда изменил | PH-US-27, PH-US-49 |
| Участие | `subject_links`: персона ↔ выпуск, роль «гость», поля участия: доступность, тема, согласие, гонорар; своя ревизия | PH-US-49, POD-US-03 |
| Общая задача | к `tasks`: постановщик, исполнитель-участник или роль, кто принял, результат, ревизия, проверка прав проекта | PH-US-39, PH-US-40, PH-US-42, POD-US-08 |
| Роли проекта | `project_role_members`: проект, роль, участник. Роль не даёт прав | PH-US-40 |
| Повторный вход | приглашение для уже существующего участника вместо создания нового | POD-US-01 |

Выпуск подкаста как дело с чек-листом из [документа 24](24-ontology-from-user-stories.md) сюда не входит. Для этой вертикали выпуск — предмет с полями, чек-лист добавляется следующим шагом.

### Инструменты Миры

Стартовый набор «ввод» из шести функций, чтобы сохранять сказанное без переключения capability:

| Функция | Что делает |
| --- | --- |
| `conversation_set_focus` | переключить текущий проект голосом |
| `subject_find` | имя, алиас, вид, дата → до 5 кандидатов, сначала в текущем проекте, с отличительными полями и ревизией |
| `subject_update` | правка полей предмета или участия: `expected_revision`, `command_id`, ссылка на source; ответ — квитанция с новой ревизией и коротким итоговым состоянием |
| `subject_create` | новая персона или выпуск, только по явному намерению |
| `memory_commit_voice_source` | как сейчас, но проект обязателен; параметр `replaces` переносит прошлую запись при «это не сюда» |
| `memory_finish_ephemeral` | как сейчас |

Список доступных проектов уже есть в контексте старта, поэтому `projects_list_accessible` и настройки темы уходят в соседние наборы. Задачи волонтёра — отдельный набор из трёх функций: «что ждут от меня», «принять задачу», «сообщить результат», все с ревизией.

Имена предметов текущего проекта добавляются в словарь распознавания вместе с названиями проектов. Лимит общий, 100 терминов.

### MCP для dot

Те же методы сервиса доступны по MCP: `subject_find`, `subject_get`, `subject_update`. Действует право service-участника на проект. Личные проекты dot не видит. Это не второй канон и не имитация голосовой сессии.

## 5. Область, источник, ревизия, повтор

- **Область.** Личное видит только владелец личного проекта, проектное видят участники с правом на проект. Права проверяются на каждом чтении, поиске кандидатов и записи.
- **Источник.** Каждая запись и правка хранит ссылку на source и его ревизию расшифровки.
- **Ревизия.** Правка без актуальной `expected_revision` получает конфликт и текущее состояние. Чужое изменение не перезаписывается.
- **Повтор.** `command_id` формируется из source и порядкового номера действия в нём. Повтор после обрыва возвращает прежнюю квитанцию. Другое содержимое с тем же `command_id` даёт конфликт.
- **Немедленное исправление.** После квитанции Мира знает ID и ревизию. «Нет, на субботу» и «это не сюда» идут прямо в эту запись, без поиска.

## 6. Вход волонтёра

POD-US-01, POD-US-08. Выдача доступа в рамках этой постановки не выполняется.

1. Владелец приглашает волонтёра. Повторное приглашение того же человека выдаёт вход тому же участнику.
2. При первом входе у волонтёра появляется личный проект. Владелец даёт ему право на общий проект и роль «волонтёр».
3. При приветствии Мира говорит, что от него ждут в общем проекте.
4. Волонтёр голосом принимает задачу, позже сообщает результат. Каждое действие возвращает квитанцию с ревизией.
5. Владелец читает ту же сохранённую версию. Личные записи волонтёра владелец не видит.
6. После отзыва права следующие операции волонтёра в общем проекте отклоняются. Личный проект у волонтёра остаётся.

## 8. Пробы и уровень проверки

| Проба | Что подтверждает | Код | Тест | Голос |
| --- | --- | --- | --- | --- |
| 1. Новый пользователь сразу наговаривает идею | идея в личном проекте, никто другой её не видит, экран не нужен | личный проект при первом входе, фокус по умолчанию | другой участник не видит запись ни в списке, ни у Миры | на телефоне |
| 2. Известный спикер и новая доступность в текущем проекте | найдено участие, изменены поля, встреча не создана | `subject_find`, `subject_update` | квитанция, ревизия +1, нет записей календаря | на телефоне |
| 3. Два Иванова или два выпуска | один вопрос, ни слияния, ни дубля | кандидаты с отличиями | два кандидата → нет записи до ответа | на телефоне |
| 4. Новость другого проекта и личная мысль в одной реплике | раздельные цели, личное в личном проекте | несколько commit по одному source | права по каждой цели | на телефоне |
| 5. Пятница → суббота, «это не сюда», повтор после обрыва | тот же предмет, перенос записи, без дубля и перезаписи | `expected_revision`, `command_id`, `replaces` | повтор → та же квитанция; устаревшая ревизия → конфликт | на телефоне с обрывом сети |
| 6. Волонтёр: вход, принятие, результат, отзыв | одна личность, общая версия, отказ после отзыва | общие задачи, приглашение для существующего участника | повторный вход тот же `actor_id`; после отзыва отказ | два телефона |
| 7. Переключение проекта голосом и вручную | экран и Мира сразу в новом проекте, разговор продолжается | фокус, ручной выбор вверху | после переключения записи идут в новый проект | на телефоне |

Тест на заглушках не засчитывается как голосовая приёмка.

## 9. Порядок

1. **Личный проект, всегда заданный текущий проект и права на память.** Это обязательное условие до входа второго человека. Пробы 1, 4 и 7.
2. **Предметы, участие и функции ввода.** Пробы 2, 3 и 5.
3. **Общие задачи, роли, повторный вход волонтёра.** Проба 6.
