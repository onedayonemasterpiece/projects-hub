# Projects Hub — спецификация живой совместной работы

**Ревизия 2 от 27 сентября 2026. Статус: спроектировано для реализации, не принято как работающее приложение.** Имя «Содей / Sodey» остаётся предложением; репозиторий и consumer `projects-hub` не переименовываются.

## Что изменено по прямому уточнению владельца

Это один продукт в двух полноценных приложениях — PWA и Android — с практически единым интерфейсом. Android обладает дополнительными платформенными возможностями, но не является тонким спутником веб-приложения.

Основной сценарий — непрерывный Live-разговор: человек говорит, агент слушает, отвечает, уточняет столько, сколько нужно, и выполняет разрешённые действия. Свободного текстового composer и формы отправки обычной реплики нет. Текст выводится для чтения, а простые варианты выбираются голосом или кнопками.

Проекты можно менять голосом и по смыслу разговора; ручной переключатель необязателен. Агент может работать по нескольким разрешённым проектам, но каждое сохранение имеет определённый адресат. Неясное сохраняется приватно и уточняется, не теряется и не попадает случайной группе.

Длинная речь без сети надёжно записывается с VAD, автоматически доставляется после восстановления связи и целиком попадает в дальнейший диалог. Ответ модели не заменяет сохранение источника. Значимые эпизоды получают отдельные Markdown с полной расшифровкой; по прежним разговорам можно искать и возвращаться к ним позднее. Новый разговор не удаляет предыдущую недоставленную запись.

Словари развиваются по разрешённым GitHub-документам и поправкам пользователя. Используются проверенные принципы Record Idea Hub и Wonderful Lections: происхождение терминов, версии контекста, акустическая/смысловая совместимость и сохранение неопределённости.

## Продукт и технические границы

Цель: **идея → обсуждение → решение → принятое обязательство → проверенный результат**. Надёжность источника — обязательная часть этого цикла, не факультативная диагностика.

Один backend на DevCoveer; документы и архивные источники — в разрешённых GitHub repo; оперативные состояния и очереди — в прикладной PostgreSQL. Общая authority ai-resource-control остаётся единственной системой Live-квот и не хранит содержание продукта. Транспорт принадлежит live-interaction. Работающий Record Idea Hub не отключается.

Исследованный runtime baseline — `d4f740df85f7c79e687a88b95e5f86bcee11e8bf`: ресурсный адаптер и offline-тесты, не полноценные приложения/backend. Его одно-проектный ProjectScope не является готовой многопроектной авторизацией. Договор [resource-rollout.md](../resource-rollout.md) сохраняется; обновление source/multi-project/dictionary adapters ещё требуется реализовать и проверить.

## Происхождение и статус

Первоначальный срез — `idea-hub@f9b7991c973282f111ef46742cd8cc1de4139469`, 18 прочитанных текстовых расшифровок. U02 — прямое сообщение владельца в этой беседе от 27 сентября, а не придуманная девятнадцатая голосовая. U02 отменяет первоначальные рекомендации о тонком Android, обязательном текстовом вводе, Send/Edit форме, ручной маршрутизации и лимите вопросов. Инженерные числа (20 секунд как страховка архивации, временный retention, checkpoint) помечены как проектные предложения для проверки.

Документация, JSON и их tests не доказывают запись настоящего микрофона, отсутствие потерь, готовность модели или прохождение 30 продуктовых gates. Все не выполненные сценарии остаются not_run. Условия выбранного провайдера и допустимость обработки реальных данных проверяются до пилота. Исходные голосовые не переписываются и не закрываются автоматически из-за появления спецификации.
