# Качество: не заставлять человека повторно наговаривать потерянное

[Индекс](README.md) · [Договор записи и памяти](10-conversation-memory.md) · [Проекты/словарь](11-routing-and-vocabulary.md).

Ревизия 2, 27 сентября 2026. Все численные параметры и критерии ниже — цели/тестовые сценарии, не результаты ещё не созданного приложения.

## Главные инварианты

Полученная речь сохраняется независимо от памяти модели. Ни потеря сети, ни Stop, ни новый разговор, ни смена проекта, ни ошибка провайдера не разрешают удалить единственный источник. Каждому принятому блоку соответствует локальная или серверная durable-квитанция, затем полный transcript и предусмотренный архив.

Нельзя показывать «всё сохранено», если есть непроверенный хвост, неполный manifest или незавершённая материализация. При этом человеку не нужно разбираться в состоянии каждой RPC: нормальная работа автоматически доставляет и восстанавливает, краткий статус говорит о реальном положении, исключение имеет понятную причину.

Надёжность источника и полезность анализа измеряются отдельно. Полностью доставленные байты не доказывают, что модель верно поняла отрицание, имя или цифру. Правильный ответ не доказывает, что исходная речь попала в Markdown.

## Независимые состояния

Запись: recording → checkpointed → sealed → server_durable → transcript_complete/uncertain → archive_pending → archive_verified. Значимое и неопределённое не отбрасывается из-за длительности или timeout. Temporary non-archive disposition допустим только для полностью обработанной краткой реплики по явной политике.

Разговор: active → waiting_connectivity / receiving_buffered / awaiting_answer / suspended → resumed/closed. Conversation ID независим от provider socket. «Новый разговор» сохраняет прежний и отделяет его будущий ответ.

Команда: interpreted → authorized → pending/confirmed → executing → verified / failed / outcome_unknown. Подтверждение не отдельная обязательная форма: ясное голосовое намерение уже может быть достаточным. Кнопка и голос используют один логический ID.

Обязательство человека: proposed → accepted/declined → in_progress/blocked → done/cancelled. Успех AI-инструмента не равен выполненной человеком задаче.

## Отказы и требуемое поведение

| Отказ/событие | Что должно произойти |
| --- | --- |
| Нет сети при старте | Запись начинается локально; несколько минут речи сохраняются без выбора особого режима |
| Сеть вернулась посреди фразы | Микрофон не перезапускается; агент не отвечает по недоставленному началу |
| Сеть снова исчезла при загрузке | Передача продолжается по receipt; нет дублей и пропущенных диапазонов |
| Stop / Новый разговор | Источник сохраняется; Stop не означает delete, прежний ответ не проигрывается в новой беседе |
| Приложение/worker перезапущены | Восстанавливаются checkpoint, manifest, исходный conversation и состояние команд |
| Закончилась память/недоступно локальное сохранение | Явная ошибка и остановка ложного recording state; старые записи не очищаются молча |
| VAD не работает/сомневается | Консервативный захват, не потеря возможной речи ради экономии |
| Provider ответил, transcript пришёл позже | Ответ не завершает source pipeline; поздние данные сопоставляются с исходным turn |
| Частичная расшифровка | Восстановление по сохранённому аудио; summary не подставляется вместо пропавшего текста |
| GitHub недоступен | Durable source удерживается, archive_pending и автоматический retry; нет ложного «архивировано» |
| Source .md создан, ответ commit потерян | Reconciliation по ID/пути/ревизии, не второй source-файл |
| Модель получила только часть большого пакета | Не заявлять полный разбор; обработать все диапазоны или показать незавершённость |
| Старое поручение доставлено спустя сутки | captured_at и timezone сохранены, актуальность и внешние последствия проверяются заново |
| Два устройства | Чужой микрофон/календарь не получает команду; источник привязан к своему origin |
| Потеря права на проект | Материал остаётся приватно доступным автору в разрешённых пределах; новая групповая запись не выполняется |
| Ответ внешнего create потерян | Сначала проверить исход, а не повторять неидемпотентное действие |
| Нет бюджета/authority/provider | Действует общий ресурсный договор; сохранение речи не прекращается из-за отсутствия AI |

## Механика надёжности

Локальный журнал, устойчивые идентификаторы, упорядоченные диапазоны, финальный manifest, транзакционные receipts/outbox, ограниченные повторные попытки, reconciliation и fencing поздних результатов. Один logical recording не превращается в много Markdown из-за транспортных чанков. Проблема одной группы не блокирует независимые записи остальных.

Pre-roll и speech hangover защищают начало/конец фразы. Тихая речь, длинная пауза, шум, Bluetooth, перебивание и собственное воспроизведение проверяются на реальных устройствах. VAD не определяет ценность мысли и не завершает разговор автоматически. Падение детектора не переводит всё в «тишину».

Требуется измерить незакоммиченный хвост и задержку durable checkpoint. Ориентир активного захвата — checkpoint примерно раз в секунду, но MediaRecorder timeslice не является обещанием такого интервала. Для восстановимого контейнера нужны отдельные проверки; недозакрытый M4A нельзя считать читаемым только по наличию файла.

Архивная очистка разрешена по полному source/readback/backup-договору, а не по UI-статусу model responded. Для pending и unresolved записей нет автоматического TTL-удаления. После физической утраты единственного офлайн-носителя невозможно восстановить то, что никогда не было передано; приложение не скрывает эту границу обещанием абсолютной неуязвимости.

Ровно один внешний эффект достигается логическими ID и проверкой исходов там, где это поддерживается. Не обещать exactly-once всех оплаченных provider calls при любой потере сети. Неизвестный результат не превращается ни в успех, ни в новый create без проверки.

В G23 нужны контрольные факты в начале, середине и конце записи, включая имя, число, отрицание и поправку проекта. Сверяется и архив, и смысл ответа модели. Одна checksum-проверка аудиофайла не является доказательством, что весь материал использован.

## Измерения и выпускной статус

Цели интерфейса: локальный захват p95 до 0,5 с на поддерживаемом устройстве, немедленная локальная реакция Stop, понятное сообщение об ожидании при заметной задержке. Durable checkpoint не должен превращать Live в медленную пакетную отправку; его добавленная задержка измеряется отдельно от provider latency.

Метрики: потерянные подтверждённые диапазоны (цель 0), полнота источников, ошибочное отбрасывание полезных фраз (цель 0 в приёмочном корпусе), oldest pending source, архивная задержка, число неизвестных исходов, точность терминов/маршрута, доля восстановленных разговоров и реальная задержка ответа. Это цели корпуса и мониторинга, не утверждение отсутствия будущих ошибок.

Исходные эксплуатационные ориентиры сохраняются как неутверждённые цели: 99,9% доступности прикладного ядра, disaster RPO до 15 минут и RTO до 60 минут. Для обещания более сильной сохранности нужны соответствующие backup/репликация и restore drill. Проверенная архивная запись и текущий незафиксированный микрофонный хвост имеют разные гарантии.

Каждый gate хранит среду, версии, устройство, вход, ожидаемый/фактический результат и свидетельство. Все ещё не выполненные gates остаются not_run. Проверка Markdown/JSON и offline contract tests не являются реальным Live, доказательством сохранности телефона или бизнес-приёмкой. Утрата подтверждённой записи, межгрупповое раскрытие, повтор внешнего эффекта и ложный успешный статус блокируют соответствующий выпуск.
