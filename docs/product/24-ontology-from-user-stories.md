**Основание:** 72 истории [реестра](user-stories.md), собранные из голосовых владельца с конца августа по 14 октября 2026 года и из документов подкаста в idea-hub.
**Отношение к другим документам.** Принятые решения владельца из [документа 21 §9](21-project-information-unified-access.md#9-решения-и-открытые-вопросы-после-реальной-сессии) сохраняются. Модель в §3–§4 [документа 23](23-collaboration-swiss-watch-proposal.md) заменяется этой, правила надёжности и Slack-синхронизации из документа 23 остаются.

## 1. Коротко

- **Пять сущностей и шаблон** покрывают все 72 истории: участник, проект, запись, карточка, обращение. Шаблон вида проекта задаёт поля, фазы и проверки.
- **Сказанное отделено от поддерживаемого.** Запись — это то, что сказано, она не меняется. Карточка — то, что команда ведёт и дополняет.
- **Голосование, встреча, напоминание, согласование, приглашение и верификация — одно обращение.** Различается только правило ответа.
- **Slack связан четырьмя связями:** канал с проектом, тред с карточкой-делом, сообщение с записью, учётка с участником. Используются только бесплатные возможности Slack.
- **dot — исполнитель, а не звено цепочки.** Ввод, поиск, брифинг, задачи, встречи и голосования работают через Миру и бота Миры в Slack без dot. dot нужен для анализа, исследований, импорта и сложных правок.

## 2. Схема

```
УЧАСТНИК ············ человек │ агент (Мира, dot) │ бот (VibePublish, импорт)
  │ учётки: Slack, ChatGPT, Telegram, телефон
  └─ членство в проекте: права + проектные роли (менеджер, волонтёр, верификатор…)
                │
ПРОЕКТ ─── вид проекта ───► ШАБЛОН
  паспорт: цели,              типы карточек · поля · фазы · проверки
  ценности, политика          правила уведомлений
  подключения: каналы Slack, репозиторий, внешние чаты, база знаний…
     │
     ├─ ЗАПИСЬ ──── дополняет ────► КАРТОЧКА ◄──── о чём ──── ОБРАЩЕНИЕ
     │  что сказано                 что ведём                  кого ждём
     │  голос Мире, сообщение       дело: выпуск, мероприятие,  спросить · сделать · выбрать
     │  Slack, звонок, легенда,     кампания, доработка,        напомнить · рассмотреть
     │  выжимка чата, файл          инцидент                    кому: участник │ роль │
     │  не меняется, хранит         материал: идея, документ,   группа │ агент │ себе
     │  автора и источник           решение, риск, гипотеза,    правило ответа · срок
     │                              персона                     итог меняет карточку
     │
     └─ ПРЕДСТАВЛЕНИЯ, не данные: доска · таблица · карточки · брифинг · колокольчик
                                  «что нового» · активность

СЛУЖЕБНЫЙ СЛОЙ: журнал изменений · квитанции команд · доставка в каждое окно
```

## 3. Сущности

| Сущность | Что это | Нужна историям | Чем не является |
| --- | --- | --- | --- |
| **Участник** | Человек, агент или бот. Стабильный ID, внешние учётки, членство в проектах с правами и проектными ролями | 02, 04, 05, 39–47, 55, 67–68 | Учёткой Slack: учётка только связана с участником |
| **Проект** | Цель и паспорт, вид проекта, подключения к каналам Slack, репозиторию, чатам и внешним базам | 01–03, 06–07, 31, 38, 66 | Каналом Slack: проект может иметь несколько каналов |
| **Запись** | Всё сказанное или полученное: голос Мире, сообщение Slack, расшифровка звонка, легенда, выжимка чата, файл. Автор, время, источник, ревизия источника. Не меняется, может быть скрыта при удалении в источнике | 06–13, 16, 22, 49, 53, 67 | Рабочим документом: из записи дополняют карточку |
| **Карточка** | То, что команда ведёт и дополняет. Тип из шаблона. Поля, фаза, проверки, связи, ревизия с автором правки. **Дело** имеет ответственного и срок. **Материал** имеет версии и состояние знания | 14, 18–19, 24, 27–28, 31–38, 48–52, 55–56, 63 | Копией текста записи и отдельной таблицей на каждый тип |
| **Обращение** | Всё, где кого-то ждут сейчас. Вид, адресат, варианты, правило ответа, срок, ответы, итог | 13–14, 25, 34, 39–48, 51, 55–58, 62, 68 | Карточкой: дело живёт долго, обращение закрывается ответом |
| **Шаблон** | Настройка вида проекта: типы карточек, обязательные поля, фазы, проверки, какие проверки рождают обращения, кого уведомлять | 08, 31–37, 52, 57 | Программируемым workflow-движком: это данные, а не код ([07](07-delivery.md) запрещает BPM-конструктор) |

**Почему карточка одна на дела и материалы.** Обоим нужны одни и те же механизмы: тип из шаблона, поля, связи, ревизии с автором и дополнение аналитикой. Различаются они двумя признаками: у дела есть ответственный и срок, у материала — версии и состояние знания. В коде это могут быть две таблицы. Для пользователя и для Миры это одно понятие «карточка».

**Почему запись отдельно.** Владелец требует «дополнять существующее, а не плодить новое». Для этого исходный ввод нужно хранить неизменным с автором и источником, а дополнять уже карточку. Slack показывает историю только 90 дней, поэтому сообщение должно стать записью в projects-hub, иначе оно пропадёт.

## 4. Минимальные поля

| Сущность | Поля |
| --- | --- |
| Участник | `id`, тип: человек, агент или бот, имя, учётки, устройства |
| Членство | участник, проект, права `viewer`, `editor`, `owner`, проектные роли, срок действия |
| Проект | `id`, вид, название, паспорт как ссылка на документ, каналы Slack, репозиторий, внешние чаты, подключённые возможности, правила уведомлений |
| Шаблон | вид проекта; для каждого типа карточки: поля с признаком обязательности, фазы, проверки с ответственным по умолчанию и признаком «рождает обращение»; правила уведомлений |
| Запись | `id`, проект, автор, окно: Мира, приложение, Slack, звонок, чат, импорт; внешний ключ, например канал и `ts` Slack; время; текст или ссылка на аудио и файл; ревизия источника; признак удаления; связанные карточки |
| Карточка | `id`, проект, тип, заголовок, поля, фаза, проверки, ответственный и срок для дела, документ как репозиторий, путь и SHA, связи, треды Slack, ревизия, автор правки |
| Проверка карточки | пункт, состояние: не проверено, не готово, готово, не применимо с причиной; ответственный, дата, основание |
| Обращение | `id`, проект, о чём: карточка или запись; кто обратился; вид: спросить, сделать, выбрать, напомнить, рассмотреть; кому; варианты; правило ответа; срок; когда проверить; кого ждём; состояние; ответы с автором и окном; итог и его применение к карточке |

Состояние обращения хранится одним из четырёх значений: открыто, закрыто с итогом, отменено, истекло. «Просрочено», «требует внимания» и «полнота карточки» вычисляются, а не хранятся.

| Себе со сроком | напоминание 43 |

Итог обращения меняет карточку: выбранный концерт, новую дату, заполненное поле, принятый результат. Молчание не превращается в согласие, нет кворума — значит «решение не принято».

## 6. Связка со Slack

```
SLACK (бесплатный тариф)                   PROJECTS-HUB
канал ─────────────────────────────────► проект           канал → ровно один проект;
                                                          несвязанные каналы не захватываются
  тред ────────────────────────────────► карточка-дело    тред может быть без дела;
                                                          у дела может быть несколько тредов
    сообщение ─────────────────────────► запись           правка = новая ревизия,
                                                          удаление = скрытый текст и след
пользователь ──────────────────────────► участник         через внешнюю учётку
файл в сообщении ──────────────────────► файл проекта     ссылка Slack = происхождение
упоминание бота ───────────────────────► команда          создать или обновить карточку,
                                                          сохранить решение, ответить
```

Обратно, из projects-hub в Slack, бот пишет только по правилам:

| Событие в projects-hub | Что появляется в Slack |
| --- | --- |
| Новое дело в связанном проекте | Сообщение бота в канале проекта со ссылкой на карточку. Его тред становится тредом дела |
| Обращение по делу | Ответ в треде дела с упоминанием адресата |
| Выбор или голосование | Сообщение с кнопками. Ответ кнопкой и голосом Мире считается одинаково |
| Блокер, важное изменение, итог | Ответ в треде дела |
| Доработка | Тред в канале разработки проекта |
| Идея, заметка, личная запись | Ничего, пока участник явно не поделился |

Всё это делается бесплатными возможностями Slack: бот пишет сообщения, читает историю связанных каналов, получает упоминания и нажатия кнопок. Платные группы пользователей, Workflow Builder, гостевые аккаунты и Slack Connect не используются. Поэтому поручение роли в Slack упоминает участников поимённо.

Владелец спрашивает, что надёжнее для переноса данных из Slack: dot или собственный бот Миры. Предложение: собственный бот projects-hub для захвата, упоминаний и отправки, dot — для анализа поверх сохранённых данных. Обоснование в [документе 23 §5](23-collaboration-swiss-watch-proposal.md#5-синхронизация-со-slack-взаимная-и-неблокирующая).

## 9. Кандидаты в MVP

Самый тонкий срез через всю цепочку «сказал → сохранено → кого ждём → сделано → узнали». В него входят только истории с реальностью «было» или «нужно». Окончательный список подтверждает прогон с Мирой.

| Шаг цепочки | Истории |
| --- | --- |
| Проект и Slack | PH-US-02, PH-US-03 |
| Ввод | PH-US-06, PH-US-11, PH-US-12 |
| Поиск и обзор | PH-US-14, PH-US-17 |
| Аналитика | PH-US-25 |
| Workflow | PH-US-31, PH-US-32, PH-US-33 |
| Поручения | PH-US-39, PH-US-42, PH-US-43 |
| Встречи | PH-US-48 |
| Сбой и разработка | PH-US-13, PH-US-63 |

Этот срез затрагивает все пять сущностей и шаблон. Голосования, внешние чаты и межпроектные сценарии идут следующим шагом на тех же сущностях без новых таблиц.

Каждая история MVP получает Gherkin-сценарий основного пути и один-два сценария сбоя: Slack недоступен, dot молчит, источник изменился. Требования надёжности из [документа 23](23-collaboration-swiss-watch-proposal.md) проверяются на этих сценариях.

## 10. Что сознательно не входит

- программируемый workflow-движок и BPM-конструктор;
- сложные взвешенные схемы голосования сверх рекомендательного и решающего веса;
- платные возможности Slack и полное зеркало несвязанных каналов;
- автоматическое создание задач из любой реплики без явной команды;
- отдельная таблица на каждый тип карточки.
