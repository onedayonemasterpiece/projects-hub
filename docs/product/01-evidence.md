[Общий индекс](README.md). Последнее обновление исследования: 2026-10-02. Реестр использует immutable GitHub-ссылки на конкретные source snapshots: исторические V01–V20 остаются закреплены на сентябрьском срезе, свежие V21–V24 — на октябрьском; `contract.json.source_snapshot` обозначает последний sweep, а не обязан быть SHA каждой исторической записи.

## Метод и граница полноты

Изучены оригинальные текстовые расшифровки 24 релевантных голосовых: 13 формирующих/уточняющих текущий продукт и 11 более ранних. Базовый индекс voice inbox просмотрен за 28 августа — 28 сентября; 2 октября дополнительно проверены свежие записи по Projects Hub, требованиям, voice UX и экспертному дискурсу; поиск проведён по разным написаниям проекта, коллективной работе и связанным продуктам. GitHub code search отставал от main, поэтому новые записи найдены через актуальное дерево и прямой поиск в синхронизированной копии. Это не утверждение, что все записи архива прослушаны или что семантически связанные записи невозможно пропустить.

Время в идентификаторах сохранено из исходных файлов; не пересчитывать его в часовой пояс читателя без исходного timezone. Аудио повторно не прослушивалось. Автоматические выжимки и старые советы модели не равнозначны словам владельца. Неопределённые фрагменты не домысливаются.

## U04: свежий review и межпроектная архитектура, 2 октября 2026

V21–V24 подтверждают, что WSS-переход нельзя рассматривать отдельно от эксплуатационных инвариантов. Требования Projects Hub теперь дополнительно защищены в `.devcoveer/requirements.json`; WSS/multi-user, shared OAuth, Regional Knowledge, POI ownership и Android self-update сведены в [16-wss-multi-user-reliability.md](16-wss-multi-user-reliability.md).

Межпроектная граница фиксируется так: Regional Knowledge владеет книгами/журналами и evidence/provenance, Street Story — canonical regional POI identity/claims/contradictions, Projects Hub — разговором и экспертной work surface. Мира получает Regional Knowledge как узкую evidence capability после user-approved resource-bound OAuth delegation, а не как второго агента и не через пересылку Projects Hub token.

## Эволюция замысла

Сначала появился надёжный личный голосовой inbox. Затем — общие банки идей для групп, личный бизнес-помощник и клиент рабочих интеграций LADENO. Новые голосовые добавили то, чего нет в простом диктофоне: обратный диалог, согласование позиций разных людей и фиксацию совместного результата. Поэтому новое ядро — координация людей, а не ещё одна оболочка над транскрипцией.

LADENO остаётся архитектурной родословной; Record Idea Hub — работающим предшественником захвата. Projects Hub — самостоятельный продукт с собственными доступами и жизненным циклом групповой работы. Никто не получает доступ к личному idea-hub владельца только из-за участия в новом продукте.

## U02: прямое уточнение владельца, 27 сентября 2026

U02 — сообщение в текущем диалоге после первого анализа, не новая найденная голосовая. Владелец уточнил: PWA и Android — полноценные приложения с практически единым UI и дополнительными возможностями Android; свободный текстовый ввод не нужен; основа — Live-разговор, а не форма отправки/редактирования. Проекты выбираются также голосом и агентом по контексту. Вопросов может быть столько, сколько нужно для результата.

Длинная речь без сети должна сохраняться с VAD и целиком аудио доходить до центрального Live-агента после восстановления связи. Сброс/новый разговор не означает утрату записанного. Live-agent сам решает через function call, нужен ли отдельный постоянный Markdown и к каким проектам его связать; фиксированный порог длительности не подменяет semantic решение. Словари переиспользуют подходы Record Idea Hub и Wonderful Lections и пополняются тем же Live-agent по разрешённым документам.

Эта ревизия отменяет противоречащие рекомендации первого анализа. Конкретные правила архивации, временного retention и checkpoint — инженерные предложения, не дословная формулировка владельца. Проверенные источники словарей перечислены в [документе 11](11-routing-and-vocabulary.md); обновлённый [Live-контракт](live-contract.json) связан с U03.

## Актуальные разрешения конфликтов

| Напряжение | Решение ревизии 2 |
| --- | --- |
| Сложная координация и простой вход | Непрерывный Live-разговор, одна основная кнопка, контекстные выборы; без composer/формы отправки |
| Разные платформы | Два полноценных приложения с единым UX; Android расширяет возможности, не заменяет общий сценарий |
| Много проектов | Агент меняет фокус по голосу/смыслу, уточняет неоднозначность; сервер проверяет каждый целевой объект |
| Личное и общее | Личный многопроектный разговор и приватный исходник; группам только разрешённые фрагменты |
| Сохранность и полезность архива | Сначала durable source; затем центральный Live-агент принимает semantic disposition через function call. Жёсткий порог длительности не решает ценность |
| Отсутствие сети | Полная durable запись/manifest; после связи исходное аудио deliberate buffered turn поступает центральному Live-агенту, который сам транскрибирует/понимает и вызывает нужные functions |
| Новый разговор | Прежний источник сохраняется и ждёт продолжения, а не смешивается с новой беседой |
| Вопросы модели | Столько, сколько нужно для цели, без повторения уже известного и искусственного лимита |
| Общий ресурс | Существующие SDK и quota authority; запись не теряется при отсутствии AI |
| Словарь | Самостоятельное grounded-пополнение по документам/поправкам, версии и область доступа |
| Библиотека медиа | По V06 позднее; надёжный архив исходной речи, напротив, обязателен в MVP |
| Android-обновления | По V19 — без постоянной ручной переустановки. MVP использует обычный безопасный Android install flow с проверкой версии/целостности; privileged silent update не требуется |
| Готовность к событию | По V20 — календарная запись не означает «готово». У события может быть короткий шаблон DoD, lead time и недостающие материалы; ассистент создаёт конкретные follow-up действия, а не универсальный workflow |

## Материализация

Этот пакет — owning product specification для Projects Hub. Исходные голоса и их исторические расшифровки остаются в IdeaHub без переписывания. Добавляется обратная ссылка из IdeaHub; закрытие registry/intake требует отдельной проверки полного маршрута и не подразумевается публикацией этих документов.
