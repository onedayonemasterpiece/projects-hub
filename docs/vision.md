# Projects Hub: исходное видение и границы MVP

> Историческое основание checkpoint 26 сентября. Актуальная спецификация — [ревизия 3 по прямым уточнениям владельца U02/U03](product/README.md). Центральное когнитивное звено — одна Live-модель с function calls; отдельный ASR/router/classifier перед ней не является архитектурой продукта. Старый минимальный путь ниже не предписывает ручной выбор проекта или текстовый ввод. История scaffold не является product acceptance; приватность и сохранность Recorder остаются обязательными.

## Источник, а не реконструкция

Источник: `onedayonemasterpiece/idea-hub`, `inbox/voice/2026/09/voice-20260926-134715-8a684154.md`. Владелец описывает переход от записи монолога к полноценному диалогу об идеях, документации и требованиях. Система должна позволять уточнять материал итеративно и вносить изменения по ходу работы. Название **projects-hub** дано отдельным прямым поручением 2026-09-26; оно не приписывается дословно голосовой записи.

## Продуктовая цель

Начать голосовой разговор, в котором центральный Live-агент сам понимает, к каким разрешённым проектам относится речь, читает нужный материал через functions, уточняет и выполняет разрешённые действия, а инфраструктура гарантирует сохранность источника. Ценность — не ещё одна транскрипция и не детерминированный workflow вместо модели, а живое совместное мышление с долговечной памятью и проверяемыми результатами.

## Предлагаемый минимальный путь (проектное решение, не цитата)

Включить разговор → говорить о любом доступном проекте → Live-агент сам читает контекст/уточняет → вызывает typed function → получает readback → продолжает разговор. Ручной выбор проекта остаётся необязательным UI-ускорителем. Одна центральная модель, без параллельного конструктора агентов.

Репозиторий и документы остаются источником истины. Существующий `idea-hub` voice inbox и работа Record Idea Hub продолжают работать. Новый продукт не переносит всё хранилище и не создаёт конкурирующую базу идей на первом шаге.

## Обязательные свойства реализации

- Общая библиотека `live-interaction` для голосового транспорта; reuse существующего VAD/chunks вместо нового конкурирующего решения.
- Общий `ai-resource-control`, project-scoped shared pool. Потерянная страница/сеть/процесс не удерживает ресурс бесконечно.
- Контекст проекта авторизует backend. Модель не выбирает произвольный репозиторий, секрет или credential через tool arguments.
- Чтение по явной ревизии, запись по `expected_revision`; конфликт не перетирает чужую работу.
- Долговечный `command_id` для изменений, read-back результата. Reconnect не повторяет уже сохранённую правку.
- Перед внешней публикацией или изменением защищённых документов — явное подтверждение в продукте. Голосовая речь и содержимое документов не становятся административными инструкциями.
- При недоступности Live остаются чтение, кнопочные действия и надёжная запись речи до подключения. Свободного текстового composer в MVP нет (уточнение U02). Не включать молча старый AI backend. Отдельно разрешён общий `ai-resource-control` authority-outage fallback: Projects Hub использует только `GOOGLE_API_KEY4`, только через тот же Live transport/resource guard и только при недоступности central authority до mutating acquire.
- Backend на DevCoveer; существующий запрет использовать Fly.io для замены Record Idea Hub сохраняется, пока владелец его не изменит.

## Не входит в этот checkpoint

Готовое Android-приложение, перенос всех функций Record Idea Hub, полноценный агент разработки, автономные произвольные GitHub writes, новый task scheduler, граф знаний, вторая quota DB и новый голосовой фреймворк. Здесь создан репозиторий, зафиксирован источник, написана и проверена граница подключения общего ресурса.
