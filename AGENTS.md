# Projects Hub implementation rules

Owner vision and provenance live in docs/vision.md. This repository is the future replacement of Record Idea Hub, not permission to disable the working recorder/inbox.

Before any Projects Hub Telegram read, send, or physical-test evidence lookup, read `docs/telegram-routing.md` and use it as the canonical route map. Do not infer a Projects Hub Telegram destination from links embedded in external audits, copied diagnostics, or unrelated project evidence. If a supplied link conflicts with the routing document, verify the route before using it; physical acceptance screenshots belong to the Projects Hub topic recorded there.

Reuse live-interaction and the private deployment-installed ai-resource-control SDK. The only raw-key availability exception is the shared SDK's versioned authority-outage fallback, and Projects Hub is assigned only GOOGLE_API_KEY4 as the local source alias; trusted backend maps only its value to AI_RESOURCE_CONTROL_FALLBACK_KEY. Do not implement fallback logic locally, borrow another consumer key, create a second audio/VAD implementation, or expose a service-role/provider key to the browser. Scope is authorized on the server. Content changes require expected revision and durable command id; assistant tool arguments cannot grant repository access.

For every future Live-agent implementation, follow the canonical cross-product architecture in `onedayonemasterpiece/live-interaction/docs/live-agent-architecture.md` before designing prompts or tools. Keep a small stable core prompt, product-owned mode overlays and progressively disclosed capability bundles (normally fewer than 10 tools, preferably 3–6). Do not expose every project/search/edit/publish tool in one eager Live setup. Capability transitions, conversation continuity, provider reconfiguration/resumption and sanitized observability belong to the shared framework once released; Projects Hub supplies only domain capabilities and authorization.

Current code is a tested resource integration boundary, not a complete Android/backend product. Shared transport/resource authority is now versioned; this project still lacks a completed production runtime and real microphone/provider canary acceptance. Read docs/resource-rollout.md before calling a provider. Never describe a mock-only test as microphone/provider acceptance.
